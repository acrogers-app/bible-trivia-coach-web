# Lesson review and pilot checklist

Copy this into each lesson's review sheet (`drafts/<topic>-<n>-review.md`) and tick as you go.
A ticked list means the lesson met our rules, not that it is proven effective.

## A. Design
- [ ] 2–3 measurable outcomes written (explain / identify / compare / find in text)
- [ ] Every section maps to an outcome
- [ ] Every question maps to an outcome; none added just for count
- [ ] Word study / key term included only if it serves an outcome

## B. Sources
- [ ] Every quotation checked word-for-word against WEB (list verse and wording)
- [ ] Every non-Scripture claim has a named source (lexicon + entry number, etc.)
- [ ] Word study separates lexicon gloss from contextual meaning; no root-only argument;
      no claim that a Hebrew and a Greek word are identical in meaning
- [ ] Scripture, explanation and contested views are visibly separate and labelled
- [ ] Differing views described fairly, not ranked; `viewsDiffer` set where needed

## C. Questions
- [ ] One defensible correct answer each (re-read against the passage)
- [ ] Distractors plausible but clearly wrong; none true elsewhere in the same chapter
- [ ] No duplicate or near-duplicate questions
- [ ] Questions run from direct recall to interpretation of what the text states
- [ ] Contested questions left out (list them as deferred)

## D. Accessibility and product checks
- [ ] Large text, VoiceOver, 44pt targets, colour not the only signal
- [ ] Read works; Listen works (when built)
- [ ] Check result is recorded in Learn progress only: no XP, streak, Path, Daily
      Challenge, analytics, best-score or missed-question changes
- [ ] Validator passes (`npm run validate:topics`)

## E. Pilot (outside the app; voluntary, with consent, minimal personal detail)
- [ ] Think-aloud with 2–5 intended learners; note where they stall or misread
- [ ] Immediate check scores noted (as diagnostics, not proof)
- [ ] Optional: delayed check (~1 week) with new, comparable questions
- [ ] Issues and revisions recorded below, with date
